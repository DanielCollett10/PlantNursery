# Architecture

_Living document. Agents update it when they change how parts fit together._

> **Direction change (Oct 2026).** The game pivoted to a top-down medieval fantasy nursery with plant behaviour
> (`docs/decisions/0009`, `0010`). The sections below describe what is built today; `docs/design/migration.md`
> lists which parts are kept, reworked or retired. Planned additions: a behaviour system ticked after growth,
> bench slots with a neighbour query, and escaped plants as sim entities with floor positions.

## Simulation core (planned for M1)

| Folder | Contents |
|---|---|
| `Sim/Core/` | `SimWorld` (tick clock, command queue, event list), `ICommand`, `CommandResult`, `PlayerId`, `ICommandSink` (player input entry point) with `LoopbackCommandSink` (in-process; a network transport implements the same interface later) |
| `Sim/Content/` | Content definitions and `ContentLoader` |
| `Sim/Time/` | `GameClock`: day, minute of day, phase, season; sleep |
| `Sim/Building/` | `Grid`, layers, footprints, placement, `BuildInventory` |
| `Sim/Economy/` | `Wallet`, supplier purchases |
| `Sim/Plants/` | `Plant`, containers (plug tray, pot), growth system |
| `Sim/Genetics/` | Genes, alleles, phenotype |
| `Sim/Hands/` | Per-player held item, watering can |

- `Sim/Content/`: `ContentLoader.Load(filesByName)` takes JSON strings (`time`, `items`, `containers`, `genes`, `varieties`, `economy`, `building`, optional `time.demo`) from `Assets/StreamingAssets/Content/`, validates them and returns an immutable `ContentDb`. Errors throw `ContentException` (file + field path).
- `species.json` (T-122, beside the old `varieties.json`, decision 0011) is loaded by `SpeciesLoader` into `ContentDb.SpeciesDefs`: stages (name, days, allowed containers), `seasonMultipliers`, `geneIds`, `regrowDays`, `modules`, `sowing` (`sowInto`, `trayMode` `wholeTray|perCell`; the first stage must allow every `sowInto` container) and nested varieties (two alleles per species gene). Genes with a `speciesId` in `genes.json` belong to a species; `ContentDb.GeneDefs` keeps only the old genes (so old varieties and `Genome` are unchanged), `AllGeneDefs` has all. `species.json` is required.
- Economy values and starter kit (T-125): `economy.json` carries `qualityMultipliers` (poor/good/excellent), `potValueCaps` (small/medium/large), `qualityCareThresholds` (excellent/poor) into `EconomyConfig` (`QualityGrade`, `PotSize` index the lists). Its `starterKit.placements` (`StarterKitLoader`, into `ContentDb.StarterKit`) lists floor items with `item`, `x`, `z`, `rotation`, and for benches `planting` (`slot`, `container`, `sow` = variety, `moisture` 0..100) and `strip` (`slot`, `item`); `holds` gives stock (the crate's carry trays). Validation: unknown item/container/variety ids, non-floor items, footprints outside the plot or overlapping, `sow` must be a species' sowable container, strip items must be accepted and fit with no overlap. Planting slots are checked for duplicates only. Nothing reads `StarterKit` yet; `starterInventory` still seeds the build inventory. Tests that edit `economy.json` text normalise CRLF to LF first (Windows checkouts).
- Bench data (T-124): a Floor item with a `planting` block is a bench; `Sim/Content/BenchLoader` reads it into `ItemDef.Bench` (`BenchDef`): `planting` (`lengthUnits`, `depthUnits`, `backOffsetUnits`), `workStrip.depthUnits` and `workStrip.accepts` (`itemId`, `stripUnits` w = along, d = across). Validation: an accepted `stripUnits.d` deeper than the strip, or an unknown `itemId`, throws `ContentException`. `workStrip` without `planting` is rejected. Only `bench_3m` and `bench_4m` carry the data; `bench_standard` does not. No placement logic reads it yet.
- Item catalogue (T-123): `items.json` holds every economy.md M2 id with its Buy price. Seed/spore items carry `speciesId`, `varietyId`, `packetSeeds` (all three required together; checked against `species.json` after it loads); `carry_tray` has `capacity` 6; `watering_can` keeps `waterCapacity` 10 (price 0, not sold). `containers.json` entries use `cells`, `alongUnits`, `acrossUnits`, `drainPerHour` (8/6/4/3) and `wateringCost` (1/1/1/2) and still carry the old `dryRatePerHour` that `GrowthSystem` uses. Nothing reads `DrainPerHour`/`WateringCost` yet.
- `Sim/Building/`: `BuildState` holds the floor grid (plot size from `building.json`), placed items and the shared `BuildInventory` (seeded from `economy.starterInventory`). `CanPlace`/`CanPickUp` are query-only and return a `BuildRejection`; `PlaceItem`/`PickUpItem` commands (registered via `BuildingModule.Register`) use the same checks and raise `ItemPlaced`/`ItemPickedUp`. The rejection name is the `CommandResult.Message`. `SurfaceGrid` (constructed with `ContentDb` + `BuildState`, which it registers as the `ISurfaceOccupancy`) is the 0.1 m mini-grid: `Unit(u,v)` = cell*5+offset across the plot; a unit is usable only over a placed floor item with `providesSurface`, so touching benches form one surface. `CanPlace/Place` take rotation-aware footprints and reject `Occupied` then `NoSurface`; `FindNearestFreeSpot(item, rotation, desired, radius)` returns the nearest valid anchor (squared Euclidean, ties smallest v then u) or null. `PickUpItem` on a bench with surface items returns `HasItemsOnTop`. Surface commands/inventory wiring are not yet added.
- `Sim/Hands/`: `HandsState(ContentDb, SurfaceGrid)` holds one `HeldItem` per `PlayerId` and the `ItemContents` (plants, water charges) of surface items, keyed by surface item id. `PickUp` removes the surface item from the grid into the hand (rejects `HandsFull`, `NotHoldable`); `PutDown` re-places it via `SurfaceGrid.CanPlace/Place` (rejects `NothingHeld`, `NoSurface`, `Occupied`) and moves its contents to the new id, so plants stay attached to trays and pots. Cans are items with `waterCapacity` (items.json) and start full; `RefillCan` fills to capacity (`NoCan`); `WaterPlant` sets moisture 100 and uses a charge (`NoCan`, `CanEmpty`, `PlantDead`). Commands `PickUp/PutDown/RefillCan/WaterPlant` are registered by `HandsModule.Register`; the rejection name is the result message. `Sim/Plants/Plant` holds the full plant model (id, variety, `Genome`, growth, stage, moisture, health, counters, `CellIndex`, isDead); growth rules are not yet implemented. `Sow(player, trayId, cellIndex)` (trays/pots are surface items whose item id matches a `ContainerDef`) needs a held `seed_packet` (`ItemContents.Seeds`, initialised from the surface item's `SeedCount`; `VarietyId` null = first content variety), then creates a Seed plant (moisture 50, health 100) with `Genome.FromVariety`, and raises `PlantSown`. Rejections: `NoSeedPacket`, `PacketEmpty`, `CellOccupied`, plus `UnknownContainer`, `InvalidCell`, `StageNotAccepted`. `Compost(player, plantId)` removes a dead plant (`NotDead` otherwise) and raises `PlantComposted`.
- `Sim/Plants/GrowthSystem` (`GrowthSystem.Install(world, content, hands, clock, config?)`) is an `ISimSystem` that updates every living plant each tick (found via `HandsState.CollectPlants`, which pairs each plant with its `ContainerDef`, whether the container is on a surface or in a hand): drying, water/season factors, growth capped at the container cap, `PlantStageChanged`, root-bound counter and health loss, wilting loss, recovery, death (`PlantDied`, then no more updates) and alive/goodCare counters. `GrowthSystem.CareScore` and `GradeOf` give the A/B/C grade. Health/grace/grade values live in `GrowthConfig` (defaults from plants.md; not yet loaded from JSON). Install it after `GameClock` so the season is current.
- `Sim/Economy/`: `Wallet` (shared coins, from `economy.startingMoney`, never below 0). `SupplierModule.Register(world, content, wallet, build, surface)` handles `BuyItem(player, itemId, qty)`: only items with price > 0; rejects `InsufficientFunds` (no change), `InvalidArgument` (unknown item / qty < 1) or `Blocked` with message `DeliveryShelfFull`. `seed_packet` is placed qty times on the placed `delivery_shelf` via `SurfaceGrid.FindNearestFreeSpot` (with an accept predicate keeping the packet on the shelf), as `SurfaceItem`s carrying `SeedCount` (`seedCount` in items.json); all-or-nothing. Everything else goes to `BuildInventory`. Raises `WalletChanged` and `ItemsPurchased`. `Validate` dry-runs shelf placement and rolls it back. `DeliveryShelf` (shared with the guard) finds the shelf and gives the nearest spot on it (`FindSpotOnShelf`) or on any surface (`FindSpotAnywhere`). `SoftLockGuard.Install(world, content, wallet, build, surface, hands, clock)` is an `ISimSystem` that, on each DayStarted tick, checks wallet < seed packet price, no living plant, and no seeds anywhere; if all hold it places one free packet (shelf, else any surface, else it waits a day), sets its variety, adds a plug tray only if none is owned anywhere, and raises `NeighbourGift`. Disabled by `softLockGuard.enabled`. Installed by `SimHost` (Unity layer). Crate path (T-135, `CrateSupplier` + `Nursery`): `CrateSoftLockGuard.Install(world, content, nursery, clock)` runs the same day-start check over `Nursery` (purse < cheapest packet price with `packetSeeds`; no living plant in the crate, a bench or a hand; no unsown packet in the crate or a hand). It adds one `spores_hearthmoss_amber` as crate stock, plus a plug tray container only if none is held anywhere, and raises `NeighbourGift` with `InCrate` set. Not registered by `SimHost` yet; registering it together with `SoftLockGuard` would double-gift.
- `Sim/Time/GameClock`: `GameClock.Install(world, timeConfig)` adds the clock system (raises `DayStartedEvent`, `SeasonChangedEvent`) and the `SleepCommand` handler. Tick 0 = Spring day 1 at `dayStartMinute`; days roll at `dayStartMinute`. Phase boundaries (`morningEndMinute`, `eveningStartMinute`, `nightStartMinute`) come from `time.json`; `IsNight`, `NeedRateMultiplier` (1 by day, `nightRateMultiplier` at night) and `RealSecondsPerTick` (`realSecondsDay` / playable minutes, constant) are the one place systems ask about night. Sleep (Evening/Night only, else `RejectReason.NotTired`) calls `SimWorld.RunUntil`, which makes `Step` keep stepping tick by tick until the next day start.
- `Sim/Genetics/`: `Genome` holds two alleles per content gene (copied; `Genome.FromVariety(db, varietyId)` copies a variety exactly). `Phenotype` has the pure rules: Mendelian = most dominant allele (earlier in the gene's `alleles` list), Blend = mean. `GenomeException` for unknown genes, alleles or varieties.
- `SimWorld` owns the tick clock. `Step(n)` advances time; nothing else does. 1 tick = 1 in-game minute.
- `SimWorld` is the SimContext (decision 0014). `new SimWorld(secondsPerTick, seed)` creates one seeded `SimRandom` (`world.Random`; systems must never use `System.Random`). `NextEntityId()` returns 1, 2, 3... and never reuses an id. Systems register with `AddSystem(system, SystemPhase)` and update each tick in phase order Time, Weather, Growth, Watering, Behaviour, Mobility, Orders, Economy (registration order only within a phase; `AddSystem(system)` means Behaviour). Weather is reserved (decision 0013) and has no systems by default. Same seed plus same commands gives identical state.
- Player input goes through `ICommandSink.Submit(cmd)`; `LoopbackCommandSink` forwards to `SimWorld.Submit`. Input never calls `SimWorld` directly.
- Commands: `Submit(cmd)` queues; each `Step` tick first applies queued commands in submission order (validate, then apply, via the `ICommandHandler<T>` registered with `RegisterHandler`), then updates `ISimSystem`s. Rejections at apply time raise `CommandRejectedEvent`. `Validate(cmd)` is query-only. A paused world keeps commands queued.
- Events: handlers and systems call `Raise(ISimEvent)`; the Unity layer calls `DrainEvents()` each frame.
- State machines: `Sim/Core/StateMachine<TState>` (`0014`) holds a transition table (`Allow(from, to, guard?)`), a plain-data `Current` state and an `onTransition(from, to)` callback the owner uses to raise its event. `TryTransition` returns `TransitionResult` (`Applied`, `Illegal`, `GuardFailed`) and changes nothing when refused; `Check` is the query-only form; `Restore` sets state on load without callbacks. Plant lifecycle and mood do not use it yet.

- Containers and crate (T-130): `Sim/Plants/Container` is a pot/tray entity (id, `ContainerDef`, `WaterMeter`, `PlantIds`) whose constructor is internal; `EntityFactory(world, content).CreateContainer(id)` is the only way to build one and takes ids from `SimWorld.NextEntityId`. `Sim/Storage/StorageCrate` is unlimited and holds container entities plus counted stock (packets, carry trays) by item id. `Economy/CrateSupplier.Register(...)` is an alternative `BuyItem` handler (BuyToCrate): floor items go to `BuildInventory`, containers become entities in the crate, other items become counted stock; `InsufficientFunds` as before. Register it instead of `SupplierModule.Register` (the old delivery-shelf path, 0011, is unchanged); not yet wired into `SimHost`.

- **Container water (T-138)**: `Plants/WaterSystem` (`Install(world, containersSource, plantLookup, clock, config?)`, Watering phase) drains each `Container.WaterMeter` by `drainPerHour/60 x clock.NeedRateMultiplierAt(tick-1)` (the minute just lived, so 22:00 to 06:00 is all night), floored at 0. Per plant: `TicksAlive`/`TicksNotDry` every living tick; Dry at 0; Wilted after `WaterConfig.WiltAfterHours` (12) continuous dry hours (`PlantWilted`, lifecycle Wilted); Dead after `DieAfterWiltedDays` (3) wilted days (`PlantDied`, `IsDead`). Meter above 0 resets the counters and returns Wilted to Growing (RootBound is re-evaluated by growth, not remembered). Plants are found via delegates because there is no plant registry yet; not yet wired into `SimHost`.

- **Watering commands (T-139)**: `Storage/WaterCommands.Register(world, nursery, content)` wires `WaterContainer(player, containerId)` (`ITargetsEntity`, key `container:<id>`) and `RefillCan(player, barrelId)`. `WaterContainer` needs a held `Can` with `Charges` >= the container's `wateringCost` (`NoCan`, `CanEmpty`, `NotFound`), sets the meter to 100 and raises `ContainerWatered`; `WaterSystem` then clears Dry/Wilted on the next tick. `RefillCan` needs a held can and a placed `rain_barrel` (`NoCan`, `NotABarrel`, also for an unknown id), and fills the can to its `waterCapacity`. `Nursery.FindContainer(id)` looks for a container in the crate, a bench slot, a hand, or a pot in a carry tray. The `RefillCan` name also exists in `Sim/Hands` (the old hands path); files that use both namespaces must qualify it.

## Unity layer (planned for M1)
- Implemented: `Assets/Game/Host/SimHost.cs` (asmdef `PlantNursery.Game`). `Initialize()` loads `StreamingAssets/Content/*.json` (`UseDemoProfile` keeps/drops `time.demo.json`), builds SimWorld + GameClock + BuildState + SurfaceGrid + Wallet; `Advance(realSeconds)` steps ticks at `Clock.RealSecondsPerTick`; `Submit`/`Validate` pass commands; an accepted `SleepCommand` steps immediately to the next morning; `EventDispatched` relays drained events. `Plant Nursery/Generate Starter Scene` (`Assets/Editor/Scene`) writes `Assets/Scenes/Starter.unity`. EditMode tests: `Assets/Tests/EditMode`.
- UI (`Assets/Game/UI`, `Player/InteractionHud.cs`): every UIDocument (HUD, build panel) uses the one committed `Assets/Game/UI/GamePanelSettings.asset` (ScaleWithScreenSize 1920x1080, theme `UnityDefaultRuntimeTheme.tss`), created by `Assets/Editor/UI/GamePanelSettingsBuilder` and assigned by `StarterSceneGenerator`. Scripts never create PanelSettings. HUD sorts above the build panel (20 vs 10). HUD and shop are UI Toolkit, loaded from `Resources/UI/Hud.uxml` + `Hud.uss`; all text comes from `UiStrings` (`Resources/UI/strings.json`). `InteractionHud` shows day/season/clock/wallet/held/prompt, the NeighbourGift toast, and the computer shop (Buy sends `BuyItem`; rejections shown). Opening the shop disables `FirstPersonController` (frees the cursor); Esc/gamepad B/Close re-enables it. `SimHost` installs `SoftLockGuard`.
- `SimHost` MonoBehaviour owns the `SimWorld`, loads content, steps ticks at the real-time pace from `time.json`, and drains events.
- View scripts mirror sim state into prefabs (placeholder mesh as a child). The first-person controller sends commands.

## Data flow

Player input → Unity layer → Sim command → `SimWorld.Step` → Sim state + events → Unity layer renders.

## Build mode and put-down ghost (T-020)
`Assets/Game/Building/`: `BuildModeController` (own UIDocument, `Resources/UI/BuildPanel.uxml/.uss`) toggles with BuildToggle and lists floor items with `BuildInventory` count > 0 (choose with 1-9 or wheel). The floor ghost snaps to the aimed cell (ground-plane ray, centred footprint), R rotates, colour and rejection reason come from `SimHost.Validate(PlaceItem)`; Place submits `PlaceItem`, PickUpDrop on a placed item submits `PickUpItem`. While a Surface item is held (build mode or not) the same ghost snaps to the aimed mini-grid unit, is nudged by `SurfaceGrid.FindNearestFreeSpot(.., NudgeRadius)`, is coloured by `Validate(PutDown)`, and PickUpDrop submits `PutDown`. The only local rule is `BuildAim.CapsuleOverlaps` (floor placement blocked where the player stands). `BuildAim` is pure maths (unit-tested).

## World views (T-019)
`Assets/Game/Views/`: `WorldView` reconciles prefab instances against the full sim state every `LateUpdate` (floor items from `Build.PlacedItems`, surface items from `Surface.Items`, plants from `Hands.GetContents`), so loads rebuild and event-less changes (deliveries, gift) still appear; `RebuildAll()` forces it. `WorldLayout` is the pure cell/unit-to-metre, rotation-pivot, stage-scale and tint maths (unit-tested). `PlantView` builds the stem+leaves placeholder (leafColour tint, droop/desaturate when moisture < 20, brown-grey `#6E6253` when dead). Surface items sit on the top of the supporting floor view's renderer bounds. Held items (and plants inside held containers) are drawn by `HeldItemView`, not here.

## Neighbour graph (T-128)
`Sim/Building/Neighbours` (`new Neighbours(content, build, slotOccupancy)`) answers `Of(SlotRef)` for occupied planting slots. It maps every planting unit into one nursery-wide unit space (cell * 5; bench-local u/v rotated clockwise by `PlacedItem.Rotation`), and two slots are neighbours when units share an edge (no diagonals), within or across benches. Built only from `SlotOccupancy.PlacedSlots`, so strip items never appear. Cached; rebuilt lazily when `BuildState.Version` or `SlotOccupancy.Version` changes (`RebuildCount` is for tests).

- **Slot commands and Taken (T-132)**: `Core/ITargetsEntity` (`TargetKey` string) marks commands that fight over one target. In `SimWorld.ApplyPendingCommands`, if a command fails validation and an earlier accepted command in the same batch had the same key, the rejection is `RejectReason.Taken` (message `Taken`) instead of the generic one. `SimWorld.PendingTargets(excludingPlayer)` lists keys of queued, unapplied `ITargetsEntity` commands from other players (for smart targeting). `Storage/SlotCommands.cs`: `SlotAddress` (planting or strip `SlotRef`; `Key`), commands `PickUpFromSlot`/`PutInSlot`, and `SlotContents(slotOccupancy, stripOccupancy, hands).Register(world)` which keeps the `HeldThing` in each slot and applies the `SlotOccupancy`/`StripOccupancy` rules (planting needs a container whose id equals the slot size; strip needs the item id to equal the strip slot's item and no planted container). Not yet wired into `SimHost`.
- **HandsV2 (T-131)**: `Storage/HandsV2.cs` holds at most one `HeldThing` per `PlayerId` (container, carry tray, can, bundle, seed packet). `TakeFromCrate` (by item id or container entity id) and `ReturnToCrate` are in `Storage/CrateCommands.cs` (`CrateCommands.Register`). Returned non-container things keep charges/quality/seeds in `StorageCrate.Things`. Independent of the old `Hands.HandsState`.
- **New nursery (T-134)**: `Storage/NurseryBuilder.Build(world, content)` returns a `Nursery` (BuildState, SlotOccupancy, StripOccupancy, SlotContents, StorageCrate, HandsV2, Wallet, plant map) built from `ContentDb.StarterKit`: floor items placed through `BuildState.Place` (a kit item is lent to the inventory first), plug trays made with `EntityFactory` and `SpeciesPlantFactory` (meter and plant moisture from the kit), strip items as `HeldThing.Fresh`, `holds` into the crate (storage_crate only), purse = `startingMoney`. Planting/strip slot index is row-major (`col = slot % cols`). Ids come only from `world.NextEntityId`, so equal seeds give equal nurseries. Not yet wired into `SimHost`.
- **Carry tray (T-133)**: `HeldThing.Pots` holds the small pot entities in a held carry tray (capacity from `items.json`, 6). `Storage/TrayCommands.cs` (registered by `SlotContents.Register`; use the 4-arg `SlotContents(.., content)` constructor to read capacity) adds `TakePotIntoTray` (slot → tray; `TrayFull`, `NoCarryTray`, `SlotEmpty`, `WrongSize`) and `PutPotFromTray` (first pot → empty small planting slot; `TrayEmpty`, `SlotOccupied`). A tray with pots goes on the strip via `PutInSlot` (`StripContents.CarryTrayWithPots`) and returns intact via `PickUpFromSlot`. Pots in a tray are not in `SlotOccupancy`, so `Neighbours` never sees them. Ground set-down stays unsupported. Growth/drain of container entities is not yet ticked by a system (the old `GrowthSystem` reads `HandsState`); the tray keeps the pots' state untouched.

## Sowing (T-137)
`SowSpecies(player, containerId)` (Storage/SowSpecies.cs) sows the held packet into a container sitting in a bench slot. `SowSystem` checks the rejections and makes plants with `SpeciesPlantFactory`. The fill rule is an `ISowFillStrategy` (`SinglePlantFill` for pots, `PerCellFill`/`WholeTrayFill` per `trayMode`), picked by `SowFillStrategies`. A new mode adds a class and one table entry. Register with `new SowSystem(...).Register(world)`; it is not yet wired in `NurseryBuilder`.
